从配置、物理仿真、强化学习控制，到 RTX 相机、激光雷达、ROS2 话题和可视化。下面先看框架，再逐层说明，最后按终端步骤亲自验证。

01 · 总体框架图

主程序只运行 Go2 或 Spot 其中一种。两套机器人代码结构对称；环境与传感器数据进入同一个仿真循环，再经 ROS2 发布给 RViz 或可选的 Web Portal。

实线箭头表示主要依赖和数据流；`ros-mcp-server` 是可选消费者，主程序不依赖它启动。

02 · 一次仿真如何运行

① 启动 Kit

AppLauncher 先启动 Isaac Sim，之后才导入依赖 Omniverse 的模块。

② 建场景与策略

Hydra 读取 YAML；选择机器人环境，创建 Gym 环境并加载 ckpts/ 策略。

③ 接传感器

为每个机器人添加 640×480 相机与 Velodyne_VLS128 RTX LiDAR。

④ 仿真循环

观测送入策略，动作交给 env.step()；控制与渲染持续更新。

⑤ 发布 ROS2

Writer 输出相机图，rclpy 输出点云、里程计、TF，并处理 YOLO 回调。

频率如何对应：默认物理步长 dt=0.005 s（200 Hz），freq=40 使 decimation=5，每 5 个物理步执行一次策略 / 渲染，目标循环周期 25 ms。图像、里程计和雷达的实际话题频率还取决于 GPU 渲染、YOLO 和系统负载；请用 ros2 topic hz 实测。

03 · 逐个模块解释

以下按运行时依赖顺序阅读。每个文件链接都可从这份 HTML 直接打开相邻源码。

01

运行配置

cfg/sim.yaml

定义 robot、env_name、num_envs、freq、camera_follow 与发布开关。当前默认 Spot + obstacle + 1 个环境 + 40 Hz。切换机器人时直接改 YAML 中的 robot。

入口先执行 argparse.parse_args()，会拒绝 robot=go2 形式的 Hydra 命令行覆盖。sensor.enable_camera / enable_lidar 控制发布路径；主入口仍会先创建传感器。sim_app 字段当前未在 main.py 中读取。

02

入口与主循环

main.py

先用 Isaac Lab AppLauncher 启动 Kit，再根据配置走 Go2 或 Spot 分支，依次完成环境、地形、传感器、键盘和 ROS2 节点初始化。循环内执行 policy(obs)、env.step(actions)、dm.pub_ros2_data() 和 rclpy.spin_once()。

代码持续运行到仿真窗口关闭；验证时主动中止，不能把定时结束当作启动失败。

03

世界与地形

env/sim_env.py · terrain.py · terrain_cfg.py

sim_env.py 按名称导入 obstacle、warehouse、office、hospital、rivermark 或 terrain。obstacle 使用自定义离散障碍物高度场；terrain.py 生成高度值，再由 Isaac Lab 转成网格。其他场景引用 Isaac 资产 USD，可能需要资产服务可用。

日志里可能出现 /World/GroundPlane 找不到的语义标签警告；本次彩色、深度和语义图仍收到数据。

04

机器人环境

quadruped/go2/go2_env.py · quadruped/spot/spot_env.py

Isaac Lab ManagerBasedRLEnvCfg 描述机器人 USD、地面、光照、接触传感器、关节位置动作、策略观测和仿真参数。观测包含机身线/角速度、投影重力、速度命令、关节位置/速度与上一步动作。

平地策略加载前会把 height_scan 观测置空；两套环境还提供视角跟随函数。

05

控制与策略权重

go2_ctrl.py · spot_ctrl.py · go2_ctrl_cfg.py · spot_ctrl_cfg.py · ckpts/

键盘 W/A/S/D/Z/C 修改共享的三维速度命令张量，ROS cmd_vel 回调也写入它；策略把观测映射成关节动作。Go2 平地权重是 ckpts/unitree_go2/flat_model_6800.pt，Spot 是 ckpts/bd_spot/spot_policy.pt；Spot 支持 TorchScript 权重回退。

主程序当前只调用平地策略。Go2 粗糙地形策略函数虽存在，主入口没有选择它。

06

相机与 RTX LiDAR

go2_sensors.py · spot_sensors.py

SensorManager 对每个环境创建前置相机和 RTX 激光雷达。相机 Camera.initialize() 建立渲染产品，分辨率 640×480；雷达使用 Velodyne_VLS128 配置和 Replicator annotator 取扫描缓冲。

Spot 相机挂在 spot/body，Go2 相机挂在 Go2/base；雷达也分别挂在机器人机身下。

07

ROS2 桥接与视觉

go2_ros2_bridge.py · spot_ros2_bridge.py

RobotDataManager 建立 /clock 图、TF、里程计/位姿/点云发布器，Replicator Writer 则把 RGB、深度、语义图与相机内参送到 ROS2。节点订阅颜色图运行 YOLOv8n，再发布检测图、Detection2DArray 和 Marker。

话题前缀为 /spot_0 或 /unitree_go2_0。检测话题出现消息不等于一定有非空目标框。

08

下游展示与可选服务

rviz/spot.rviz · rviz/go2.rviz · ros-mcp-server/

RViz 配置预设相机图、点云、位姿和检测图，固定坐标系是 map。可选的 MCP Server 通过 rosbridge 的 WebSocket 操作 ROS 话题/服务；Gradio Web Portal 可查看相机并发送速度命令。

MCP / Web Portal 未纳入本轮运行验证。RViz 预设里有 depth_cloud 显示，但对应发布函数当前未启用，显示缺话题属于预设与代码不一致。

04 · 渲染链路与本机实测样本

本节图片于本机运行 Spot 与 Go2 的 obstacle 场景时，从 ROS2 话题采集，不是 README 中的示意图。图像与点云分别呈现“GPU 渲染 → 传感器数据 → ROS2 发布 → 消费端”的不同阶段。

同一场景下的 Go2

Go2 的相机安装位置和机器人姿态与 Spot 不同，所以构图不同。以下图片来自 Go2 完整主程序的稳定帧，而非独立传感器测试。

Go2 同次采样的其他图像：深度伪彩色、语义分割、YOLO 后处理图。

判读顺序：先确认彩色图内容可辨，再看深度图是否体现近远层次；语义图应有不同区域；检测图不要求每帧有框；点云应有空间结构。只有 topic list 能看到名称，不能证明图像有内容，因此还要看画面或消息字段。

05 · 你可以怎样人工自验证

以下命令针对当前机器上的安装路径。开三个终端；不要在 go2_codex 中重新安装 README 的全部依赖，以免覆盖已匹配的版本。

终端 A · 启动仿真（默认 Spot）
source /data/anaconda3/etc/profile.d/conda.sh
conda activate go2_codex
source /data/apps/ros2-humble/activate_sim.sh
cd /data/projects/Sim2Real/1029_4.5/Go2_Isaac_ros2
OMNI_KIT_ACCEPT_EULA=yes python main.py

等待 Isaac Sim 窗口显示障碍物场景与机器人。终端日志应出现 Simulation App Startup Complete、Loaded JIT checkpoint.，之后程序保持运行。首次启动可能较慢，因为 RTX 着色器需要编译。

终端 B · 检查 ROS2 消息是否真正流动
source /data/apps/ros2-humble/activate_sim.sh
ros2 node list
ros2 topic list
ros2 param get /robot_data_manager use_sim_time
ros2 topic hz /spot_0/front_cam/color_image
ros2 topic echo --once /spot_0/front_cam/color_image --field height
ros2 topic echo --once /spot_0/front_cam/color_image --field encoding
ros2 topic echo --once /spot_0/lidar/point_cloud --field width
ros2 topic echo --once /spot_0/odom --field pose.pose.position

期望出现 /robot_data_manager、/spot_0/... 话题，use_sim_time=True；彩色图高度应为 480，编码 rgb8；点云宽度应大于 0。topic hz 应持续打印频率，按 Ctrl+C 结束该命令。

终端 C · 在桌面显示会话打开 RViz
source /data/apps/ros2-humble/activate_sim.sh
cd /data/projects/Sim2Real/1029_4.5/Go2_Isaac_ros2
rviz2 -d rviz/spot.rviz

在 RViz 左侧检查 Fixed Frame = map，观察 color_image、depth_image、lidar_point_cloud 和 spot pose。若图像未显示，点击 Add → Image，手动选择 /spot_0/front_cam/color_image；点云选择 PointCloud2。预设 depth_cloud 没有对应发布话题，可禁用该 Display。

键盘控制

点击 Isaac Sim 窗口让视口获得焦点，短按 W 前进、S 后退、A/D 横移、Z/C 转向；松键后速度指令清零。camera_follow: true 会让视角跟随机器人。

切换 Go2

停止 Spot 仿真后，将 cfg/sim.yaml 的 robot: spot 改为 robot: go2，再按终端 A 的原命令启动。终端 B/C 的话题前缀换为 /unitree_go2_0，RViz 配置换为 rviz/go2.rviz。测试完可把 YAML 改回 Spot。当前入口不支持 python main.py robot=go2。

远程或离屏会话：RViz 依赖桌面 GLX 窗口。把 QT_QPA_PLATFORM=offscreen 强加给 RViz 会触发 Invalid parentWindowHandle；应在真实桌面会话中运行。本机使用 DISPLAY=:1 已成功启动 RViz 并识别 OpenGL 4.6。

06 · 调试顺序与常见故障

按层排查，别从 RViz 黑屏直接推断渲染失败：先看仿真进程，再看 ROS2 发布，再看 RViz 显示。

现象先检查解释 / 下一步
Isaac Sim 窗口打不开或 RTX 崩溃nvidia-smi；主程序日志本机已换为 570.144 驱动。确认能列出 RTX 3090；首次着色器编译可能需要数分钟。
ModuleNotFoundError: isaacsim.sensors确认 Isaac Sim 4.5 环境、相机扩展启用独立传感器脚本需要启用 isaacsim.sensors.camera 与 isaacsim.sensors.rtx；不要用系统 Python 跑 Isaac Sim 模块。
地形生成时报 turbo 色图错误python -c 'import trimesh; print(trimesh.__version__)'此环境固定使用 trimesh 4.6.4，避免新版本移除该映射后的兼容问题。
有话题名但没有图像/点云ros2 topic hz、echo --field；传感器 render product话题注册与产生有效帧是两回事；检查仿真是否仍在播放、GPU 是否完成渲染及发布开关。
RViz 空白、红色状态或缺少深度点云Fixed Frame、Topic、TF、Display 状态用 map 坐标系；必要时手动 Add。depth_cloud 是预设遗留项，当前代码未发布。
YOLO 检测图无方框先看彩色图内容，再看 /detections检测图已发布也可能没有符合阈值的目标。默认障碍柱场景未必属于 YOLOv8n 的识别类别。
ROS2 CLI 报缺 packaging 或 larkros2 launch --helpROS2 CLI 使用系统 Python；本机已在对应 Python 路径补齐两项依赖。
主动结束仿真时出现 Unable to create ROS2 node确认报错时间与程序退出时间是否相同本次 Spot 定时结束时出现该 OmniGraph 信息，但此前已采到有效 ROS2 消息。若它在持续运行阶段出现且无数据，再检查桥接扩展与节点命名空间。

建议观察的日志节点

# 在仿真运行时另开终端
nvidia-smi
source /data/apps/ros2-humble/activate_sim.sh
ros2 topic info /spot_0/front_cam/color_image -v
ros2 topic info /spot_0/lidar/point_cloud -v
ros2 topic hz /spot_0/front_cam/depth_image

如果只是要缩小范围，先将“仿真窗口是否有场景”“ROS2 图像高度与点云宽度是否有效”“RViz 是否选对话题”分别记录。这样能定位问题是在 GPU/Isaac、桥接还是显示端。

07 · 本轮实际验证范围

项目状态实际证据
